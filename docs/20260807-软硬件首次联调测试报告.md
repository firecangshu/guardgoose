# 20260807 软硬件首次联调测试报告

> 版本：v1.1.0（首次真机联调里程碑）
> 测试日期：2026-08-06 ~ 2026-08-07
> 环境：Windows 21H2 ｜ ESP32-S3 ×2（TX 发射板 MAC 尾号 29:48 / RX 接收板 MAC 尾号 88:50，COM8）
> 链路：RX 板 USB 串口 → hw.bridge 桥接器 → 边缘服务 8000 → 状态机 → 子女端 H5

---

## 一、测试结论

### 1. 全链路打通（✓）

真实 CSI 信号首次跑通完整链路：串口采集（~60 帧/秒）→ 解析 → 逐秒聚合推送 →
状态机消费（source=csi_live）→ H5 前端展示。长时间运行稳定，断线自动重连可用。

### 2. 呼吸检测能力确认（✓，条件依赖）

健康链路（RSSI -47~-49）下出现过 **7/min、共识 32/32 满分的连续锁定**，
证明锁频算法在真机上工作。但锁频对链路质量高度敏感（见不足 ①）。

### 3. 根因链定位（本次最重要收获）

```
TX 板电池掉电 ──→ RSSI 从 -48 渐降至 -60~-72
                    │
                    ▼
     子载波信噪比不足 → FFT 主频不聚簇 → 共识 0~1/32 → 呼吸无法锁频
```

证据链三条相互印证：

| 证据 | 现象 |
|---|---|
| 相关性 | 全天仅有的两次成功锁定都发生在 RSSI -47~-49 健康时段 |
| 对照实验 | 人离开连线后 RSSI 不回 -48 基线而是稳在 -55，排除人体遮挡，锁定链路本身变弱 |
| 干预验证 | 两板拉到 30cm 后 RSSI 立刻冲到 -20，物理距离即可补偿，坐实发射功率（电池）问题 |

次要因素：部署几何——坐两板侧面只收弱散射；坐到连线中点后曾出现连续 11 秒满共识锁定。

### 4. RSSI 诊断法（新增排障手段）

- 空场基线 ≈ -48 → 健康
- 人在场遮挡 LOS 掉到 -60~-72 → 正常
- 人离开后 RSSI 不回基线 → 链路本身变弱（主查 TX 供电）

## 二、本次修复的缺陷

| # | 缺陷 | 修复 | 位置 |
|---|---|---|---|
| 1 | FFT 采样率硬编码固件标称 72fps，实测仅 43~57fps，锁频数值失真 | 桥接器按实测帧率 EMA 校准（clamp 20~100） | hw/bridge.py |
| 2 | 呼吸单次误锁（真 15/min 误锁 7/min 判 shallow）直进红区紧急告警，且与跌倒候选拼合成假双证据 | 异常态统一 5s 持续防抖；无读数不清零；双证据线改用防抖态 | edge/state_machine.py、edge/config.py |
| 3 | 开机即推流，环境不合格时垃圾数据进状态机 | **开机自检（preflight）**：静默采集 15s，帧率/RSSI/底噪/空场/后端闸门五项体检，全过才推流，不过给修复建议每 10s 重测，修好自动放行；`--no-preflight` 可跳过 | hw/bridge.py |
| 4 | 自检首版底噪 EMA 跨轮残留污染第二轮判定 | 每轮自检前 reset_state 清零全部估计器 | hw/bridge.py |

回归验证：状态机单测 9/9；回放 F1 3/3、F2 0/3、F3 3/3，与基线一致，无回归。

## 三、不足（诚实清单）

1. **呼吸检测依赖链路健康**：RSSI 掉 7dB 共识即从 32/32 崩到 0~1/32，
   目前只能靠开机自检拦截，运行中链路劣化没有降级/告警机制。
2. **底噪估计器存在污染反馈环**：人在场静息强度会喂入底噪统计，
   floor 爬到 0.04+ 后显著度闸门被抬到 8x，可能反过来压死锁频。尚未修复。
3. **锁频数值待对照验证**：成功锁定值 7/min 偏低，需受试者数呼吸对照，
   排除半频锁定（真 14/min 锁成 7/min）。
4. **语音确证降级中**：Qwen TTS API 401，语音轮询走规则版降级，
   演示可用但非完整体验。
5. **30cm 近场未验证**：应急拉近后空场读数健康（RSSI -20、底噪 0.017），
   但人进场后能否锁呼吸未测——近场饱和区超出 1~3 米标定范围。
6. **部署几何敏感性高**：坐偏（侧面）即失效，对非技术用户不友好，
   缺少布放引导工具。
7. **进程管理粗糙**：本次发现两个桥接器残留进程抢同一串口，
   缺乏单实例保护。

## 五、部署 SOP 要点（详见《使用说明书与操作SOP》第 4 节）

1. 后端 `python run_edge.py`（8000）
2. 桥接器 `python -m hw.bridge --backend http://127.0.0.1:8000`（自检默认开）
3. 两板对放 1~3 米（实测最优 1.8 米），人坐连线中点、胸腔朝向连线
4. 开机前确认：TX 板满电、无空调直吹、视场无人（自检会逐项把关）
