# 护院鹅 Guard Goose · 使用说明书与操作 SOP

> 版本 v1.0 ｜ 适用系统：WiFi CSI 居家安全守护系统（边缘服务 + 子女端 H5）
> 原则：无摄像头、无穿戴，CSI 信号本地分析，原始数据不出家门

---

# 第一部分 使用说明书（子女端 H5）

## 1. 三分钟上手

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 打开 H5 地址 | 部署完成后，浏览器访问子女端地址 |
| 2 | 输入守护人称呼 | 如"妈妈"，点【进入守护】。不是账号密码，用于全程个性化称呼 |
| 3 | 浏览 4 屏引导 | 无感守护 → 呼吸监测 → 跌倒秒级告警 → 千人千面 |
| 4 | 建立守护档案（3 步） | ① 基本信息：关系/年龄/体重 ② 身体状态：健康档位/病史多选/其他疾病 AI 查询 ③ 作息：用药/跌倒晕厥史/家族猝死史 |

完成后进入守护主页，共三个底部栏目：**守护 · 事件库 · 档案本**。

## 2. 守护页（主页）

### 2.1 信号展示大卡

| 区域 | 内容 |
|---|---|
| 状态大字 | 平静 / 活动 / 疑似跌倒 / 紧急（卡片颜色随状态变：绿→蓝→橙→红） |
| 呼吸频率 | 次/分，异常时带状态 tag（过快/浅弱/消失） |
| 活动强度 | 0~1 数值 |
| 活动曲线 | 实时滚动曲线，左侧等距刻度（0.08/0.25/0.80/1.0），右侧等级分区（静止/轻微/活动/剧烈尖峰） |
| 信号来源 tag | **真实信号 / 信号弱 / 无信号 / 虚拟信号** 四态，与实际数据源实时同步 |
| 信号解读台 | 内嵌大卡底部，常驻最近两行，点开看全部分析与建议；平稳时静默不打扰 |

### 2.2 探测器检测条

显示设备连接状态：**已接通·信号良好 / 信号不佳 / 已断开**，可展开查看排障建议（天线摆位、供电、距离等）。

展开面板内有**信号接通测试**按钮：一键体检“板子 → 信号桥接器 → 后端 → 链路质量”全链路，逐项给结论与修复建议。显示接通但收不到数据时先点它，能定位到具体是哪一环断了。

**开阀自动体检**：点“真实接入”开关即自动跑一次全链路体检（桥接器没在跑会自动拉起）：通过→信号正常开始监护；不通过→大卡直接显示“故障 · 断在XX环”及修复建议，不再笼统显示“无信号”。信号大卡四态：待机（没开阀）/ 体检中 / 信号正常 / 故障（开了阀但断在某环）。

### 2.3 告警卡（仅告警时出现）

无任何文字信息，只保留两个行动入口：

| 按钮 | 行为 |
|---|---|
| **紧急联系**（蓝） | 三级自动降级拨打链：拨紧急电话 1 → 8 秒无应答自动切电话 2 → 再切电话 3；也可手动点"打不通"提前切换、点"挂断"终止 |
| **报警120**（红） | 直接调起拨号 120 |

三个电话均无人接听时，系统提示改拨 120 或联系邻居/社区上门。未填紧急电话则回退拨打老人电话。

### 2.4 演示接入

无硬件时可用演示剧本全链路体验。一个场景一个完整故事（起承转合+结局），共四个：休憩中 / 活动中 / 疑似跌倒·确认无碍·解除警报 / 疑似跌倒·风险增加·进入救护链。时长按真实判定链耗时耐配（均在一分半内，呼唤确证为急救导向 30s/15s）。风险剧本每轮随机演示一种呼吸紊乱（急促/节律紊乱/减弱骤减，均有医学背书）。演示期间信号来源显示“虚拟信号”。

演示期间探测器按剧本模式常驻“接入成功 · 信号良好”，不会自动断开；剧本播完自动从头循环（状态机每轮归零，告警不会无限叠加），直到手动关闭演示开关或开启真实接入。

## 3. 事件库

双日志结构，两个区各自独立：

| 日志区 | 内容 | 导出格式 |
|---|---|---|
| 信号检测日志 | 状态机判定的事件：区域 tag + 事件名 + 时间，附呼吸/强度/详情 | CSV |
| 程序工作台日志 | 服务运行记录：启动、子女端连接/断开、演示与真实接入开关、重置、告警生成（含个性化病因） | TXT |

交互规则：**常驻只显示最新前三行**，底部"展开全部 N 条"查看完整列表；标题行"导出"按钮浏览器本地下载，数据不经云端。右上角图标手动刷新。

## 4. 档案本

**折叠摘要原则：所有内容默认收起，标题行直接展示已填摘要，点开才修改。**

| 区域 | 说明 |
|---|---|
| 风险等级 | 常驻显示（如"高风险"），由病史自动评估 |
| 基本信息 | 标题摘要：姓名 · 关系 · 年龄；内含地址、紧急电话 1/2/3 |
| 身体状态 | 标题摘要显示当前档位 |
| 病史（可多选） | 勾选后标题显示"已选 N 项"；支持 AI 查询其他疾病，确认后入档 |
| 用药 / 历史记录 | 同上规则 |
| **已选标签卡** | 病史（蓝色）、用药（橙色）以标签形式**常驻展示**，不随折叠隐藏 |
| 保存档案 | 保存即时生效，修正系数同步注入状态机 |
| 退出登录 | 程序登出回登录页，档案与记录保留，重登后直接进首页 |
| 重置系统数据 | 清空事件库+告警并归零状态机，**档案保留** |
| 注销（档案全部清零） | 病历/病史/用药/自定义疾病全部清零，事件库不动；红色强确认防误触 |

## 5. 告警处置 SOP（子女视角）

| 告警级别 | 你会看到 | 建议动作 |
|---|---|---|
| 黄色提醒 | 告警卡弹出，守护 Tab 亮角标 | 点【紧急联系】先打电话确认老人状态 |
| 红色紧急 | 告警卡 + 提示音 + 呼吸"消失"tag | 立即【紧急联系】，无人接听换下一个号码；仍不通点【报警120】，同步联系邻居/物业上门 |
| 误报确认 | 老人接电话确认无碍 | 无需其他操作，告警卡自动收起 |

## 6. 常见问题

| 问题 | 答案 |
|---|---|
| 原始视频/音频会上传吗 | 不会。系统不装摄像头、不录音，CSI 信号全部本地分析，手机端只收到"活动/呼吸/告警"语义标签 |
| 没有网络能用吗 | 边缘服务与手机在同一局域网即可工作，不依赖外网 |
| 换老人/换家庭怎么用 | 档案本改称呼与档案即可；档案清零重来用“注销”，只清运行记录用“重置系统数据” |
| 紧急电话能填几个 | 最多 3 个，按顺序自动降级拨打 |

# 第二部分 操作 SOP（部署 / 演示 / 运维）

## 1. 环境清单

| 依赖 | 要求 |
|---|---|
| Python | 3.10+，安装依赖：`pip install -r requirements.txt`（waveguard 目录） |
| Node.js | 18+，前端依赖：`cd h5 && npm install` |
| 端口 | 后端 8000（子女端同端口托管）；开发调试另用 5173 |
| 数据库 | SQLite（waveguard.db，自动生成，含旧库自动迁移） |

## 2. 启动 SOP（每次使用）

**日常一键启动（推荐）**：双击桌面快捷方式“护院鹅子女端”（或 `启动子女端.bat`）——
启动器自动探测后端：未运行则后台拉起（无黑框，关窗不停服务），
已运行则直接开窗；子女端页面由后端 8000 端口同址托管，单端口全搞定。

```powershell
# 开发调试模式（改了前端代码要即时生效时才用）
cd waveguard
python run_edge.py          # 终端 1：边缘服务，监听 0.0.0.0:8000
cd waveguard\h5
npm run dev                 # 终端 2：开发模式 http://localhost:5173（自动代理 8000）

# 注意：改完前端代码要反映到一键启动版，需重新构建
cd waveguard\h5; npm run build   # 产物 dist/ 由后端静态托管
```

验收检查点：

- [ ] 一键启动后弹出“护院鹅 · 子女端”独立窗口，出现登录页
- [ ] 输入称呼进入守护页，信号大卡显示“无信号”（未开数据源属正常）
- [ ] 事件库 → 程序工作台日志首行：“边缘守护服务已启动”

## 3. 演示 SOP（四个完整剧本）

| 剧本 | 触发方式 | 预期时序 | 看点 |
|---|---|---|---|
| 休憩中 | 演示接入 → 休憩中 | 约 60 秒一轮，循环播放 | 回家→坐下→看电视，呼吸平稳，系统静默不打扰 |
| 活动中 | 演示接入 → 活动中 | 约 60 秒一轮，循环播放 | 做家务→歇口气→继续收拾，正常活动不误报 |
| 疑似跌倒·确认无碍·解除警报 | 演示接入 → 解除警报 | 约 60 秒一轮，循环播放 | 静止中跌倒→呼吸急促两级确证→呼唤测试→回应「我没事」→警报解除恢复正常 |
| 疑似跌倒·风险增加·进入救护链 | 演示接入 → 救护链 | 约 53 秒一轮，循环播放 | 运动中跌倒→呼吸紊乱（每轮随机：急促/节律紊乱/减弱骤减）→确证成立→侦测呼救→风险增加立即升级进救护链 |

命令行触发（调试用）：

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/source-mode/demo -Method Post `
  -Body '{"enabled":true,"scenario":"demo_fall_still"}' -ContentType 'application/json'
```

## 4. 真实接入 SOP（接硬件）

1. 启动桥接器（自动发现 RX 板串口）：

```powershell
cd waveguard
python -m hw.bridge --backend http://127.0.0.1:8000
```

2. **开机自检（默认开，通过后自动推流）**：连上板子后先静默采集 15 秒（不推流），逐项体检，全部达标才进入正式监护；不达标会给出修复建议并每 10 秒重测，修好即自动放行。

| 检查项 | 门限 | 不达标时怎么办 |
|---|---|---|
| 串口帧率 | ≥20/s | 检查 RX 板 USB 供电，确认固件在发 CSI_DATA |
| 链路质量 RSSI | ≥-60dBm（健康≈-48） | 给 TX 发射板充电/换电源，两板间距收回 1~3 米，天线竖直正对 |
| 环境底噪 | ≤0.02 | 关空调/风扇等 3 分钟再试 |
| 视场空场 | 强度 P90≤0.15 | 人离开两板连线区域、移开遮挡物 |
| 后端闸门 | 边缘服务可达 | 未开「真实接入」会自动开启；服务不可达先跑 `python run_edge.py` |

紧急跳过自检（不建议常规使用）：`python -m hw.bridge --no-preflight`

3. 硬件每秒上报样本：

```
POST /ingest/sample
{ "ts": "ISO时间", "sim_t": 秒序, "intensity": 0~1,
  "zone": "living", "breathing_rate": 次/分, "breathing_state": "normal" }
```

4. 信号来源四态自动判定：

| 状态 | 判定条件 |
|---|---|
| 真实信号 | 真实接入开启且 ≤10 秒有新样本 |
| 信号弱 | 样本间隔 10~30 秒 |
| 无信号 | 间隔 >30 秒，或所有数据源未开 |
| 虚拟信号 | 演示场景播放中 |

5. 探测器检测条实时显示连接质量，断开超 30 秒给出排障建议

## 5. 数据管理 SOP

| 操作 | 入口 | 影响 |
|---|---|---|
| 重置系统 | 档案本 → 重置系统数据 | 清事件库 + 状态机归零 + 停演示，档案保留 |
| 导出日志 | 事件库 → 各区"导出" | 本地下载 CSV/TXT，可用于备查与汇报 |
| 备份数据库 | 复制 waveguard.db | 含全部事件/告警/档案/病史注册表 |

## 6. 故障排查

| 现象 | 处置 |
|---|---|
| 8000 端口被占用 | `netstat -ano` 查占用 PID → 任务管理器结束后重启 |
| 页面空白/数据不动 | 浏览器强制刷新（Ctrl+F5）；检查 8000 是否存活 |
| 一直"无信号" | 检查数据源开关：演示接入或真实接入至少开一个 |
| 演示播了不出告警 | 剧本需要约 20 秒时序，勿中途切场景 |
| 工作台日志为空 | 日志为内存环形缓冲（200 条），重启服务后从零累积，属设计 |

## 7. 隐私与安全边界

- CSI 原始数据只在边缘设备处理，**不出局域网**
- 手机端仅接收语义标签（状态/呼吸/事件），无图像、无音频
- 登录态仅存本机浏览器（localStorage），无云端账号体系
- 病史等医疗信息存本地 SQLite，含 AI 查询结果的子女确认流程
